## علاش هاذي المرحلة مهمة

الذكاء الاصطناعي ماعادش تخصص منفصل يخص "مهندسي الـ ML" غير. إلا كنت تبني تطبيقات ويب اليوم، راهو من المرجح برشا تخدم مع API متاع AI، ولا مساعد برمجة بالذكاء الاصطناعي، ولا محتوى مولّد بالـ AI فـ خط سير عملك. ما تحتاجش دكتوراه فـ machine learning. تحتاج فهم عملي وواضح لعدد من المفاهيم باش تبني منتجات موثوقة وتتفادى الأخطاء الشائعة.

هاذي الأشياء اللي تهم فعلاً.

## 1. كيفاش تخدم الـ LLMs، بصفة عامة

ما تحتاجش تفهم backpropagation. لازم تفهم أن نموذج اللغة الكبير (LLM) يتنبأ بالكلمة الجاية بناءً على أنماط فـ بيانات التدريب متاعو، ما عندوش ذاكرة حقيقية بين الطلبات إلا كان أنت اللي عطيتو واحدة، ونجم يبان واثق وهو غالط بالكامل. هاذي النقطة الوحيدة — "الغلط بثقة"، ولا "hallucination" — لازم تأثر على كل قرار تاخدو فـ منتج يستعمل مخرجات AI.

## 2. استدعاء واجهات AI مثل أي API آخر

الخدمة مع API متاع مزود AI ما تختلفش جوهرياً عن الخدمة مع أي REST API. تبعث طلب، تاخد رد، وتتعامل مع الأخطاء وrate limits. مثال بسيط:

```javascript
const response = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "x-api-key": process.env.API_KEY,
  },
  body: JSON.stringify({
    model: "claude-sonnet-4-6",
    max_tokens: 1000,
    messages: [{ role: "user", content: "لخص هذا النص: ..." }],
  }),
})

const data = await response.json()
```

المهم موش الـ syntax — المهم إنك تتعامل مع مخرجات النموذج كنص غير موثوق ومتغير الطول لازمو validation، موش كقيمة مضمونة ومنظمة.

![مخطط تدفق طلب ورد API متاع LLM](/blog-images/llm-api-flow.svg)

## 3. الـ Prompt Engineering مهارة حقيقية تتعلم

التعليمات اللي تبعثها للنموذج تهم بقد الكود اللي يستدعي الـ API. كون دقيق، أعطي أمثلة، اطلب فورمات معين للمخرجات، وقسم المهمة الصعيبة لخطوات — كل هاذي تحسن النتائج بصفة ملموسة. ماهيش سحر — قريبة أكثر من كتابة spec مفصل برشا لمطور جديد قرا الأنترنت بالكامل ولكن ما عندوش context على المشروع متاعك بالضبط.

## 4. المخرجات المنظمة والـ Validation

عمرك ما تثق فـ LLM باش يرجع JSON صحيح 100% غير لأنك طلبتها بأدب. دايماً اعمل parse بحذر، شيل code fences متاع الماركداون قبل الـ parsing، تأكد من شكل الرد، وحضر مسار بديل إلا فشل.

```javascript
function parseModelJSON(text) {
  const clean = text.replace(/```json|```/g, "").trim()
  try {
    return JSON.parse(clean)
  } catch (err) {
    return null // تعامل مع هذي الحالة بوضوح، ما تخليش التطبيق يكراش
  }
}
```

## 5. الـ Retrieval-Augmented Generation (RAG)

النماذج ما تعرفش بيانات شركتك، ولا الكود متاعك، ولا الأحداث اللي صارت بعد تاريخ التدريب متاعها. الـ RAG هو نمط جلب معلومات ذات صلة — من قاعدة بيانات، بحث vector، مخزن مستندات — وحقنها فـ الـ prompt قبل ما تطلب من النموذج يجاوب. كمطور ويب، رايح تكون أكثر فأكثر الشخص اللي يربط هاذا الـ pipeline: بحث، جلب، حقن، توليد.

![مخطط pipeline متاع RAG](/blog-images/rag-pipeline.svg)

## 6. الـ Embeddings والبحث الـ Vector، بصفة مفاهيمية

الـ embedding يحول النص لقائمة أرقام تعبر على المعنى متاعو، بحيث النصوص "المتشابهة" تولي قريبة رقمياً من بعضها. ما تحتاجش تنفذ الرياضيات. تحتاج تعرف وقتاش feature معين يحتاج هاذي التقنية — بحث دلالي، توصيات، إزالة التكرار، تجميع — مقابل وقتاش query عادي فـ قاعدة البيانات كافي.

## 7. مساعدو البرمجة بالـ AI أدوات، موش autopilot

مساعدين مثل Claude Code، Copilot، ولا Cursor ينجموا فعلاً يسرعوا التطوير، خاصة للـ boilerplate، الـ refactors، والمكتبات اللي ما تعرفهاش. لكن الكود المولّد لازم يتقرا، يتفحص، ويتفهم قبل ما يطلع للإنتاج. تعامل مع كود كتبو AI بنفس الطريقة اللي تتعامل بيها مع pull request من مطور عمرك ما خدمت معاه — مفيد، لكن لازم review.

## 8. الأمان: الـ Prompt Injection ثغرة حقيقية

إلا كان التطبيق متاعك يخلي LLM يقرا محتوى غير موثوق (رسالة من مستخدم، صفحة ويب مجروفة، ملف مرفوع) وبعدها يتصرف بناءً عليه ولا يوريه لمستخدمين آخرين، عندك سطح هجوم جديد. تعليمات خبيثة تنجم تتخبى داخل هذا المحتوى وتحاول تسرق سلوك النموذج. تعامل مع أي نص يقراه النموذج من مصدر خارجي بنفس الطريقة اللي تتعامل بيها مع مدخلات مستخدم غير منظفة فـ query متاع SQL.

## 9. التكلفة والـ Latency قرارات منتج

كل استدعاء AI يكلف فلوس ويوخذ وقت. feature يستدعي نموذج كبير ثلاث مرات فـ كل تحميل صفحة رايح يحس بطيء ويولي غالي مع الحجم. اتعلم تستعمل نماذج أصغر وأسرع وقتاش المهمة بسيطة، اعمل caching بقوة، واستعمل streaming للردود باش المستخدم ما يبقاش يستنى قدام شاشة فارغة.

## 10. اعرف الحدود، وقولها

أثمن حاجة تنجم تبنيها فـ feature يخدم بالـ AI هي الصراحة على حدودو: وري المصادر، نبّه على الإجابات القليلة الثقة، عطي للمستخدم طريقة سهلة يصحح ولا يبلغ عن غلطة. المستخدمين يثقوا فـ منتجات صريحة على عدم اليقين أكثر بكثير من منتجات تتظاهر بالثقة.

## خاتمة

ما تحتاجش توّلي باحث فـ الذكاء الاصطناعي. تحتاج تتعامل مع الـ AI بنفس الطريقة اللي تتعامل بيها مع أي خدمة خارجية أحياناً ما تكونش موثوقة فـ الـ stack متاعك: افهم طرق فشلها، تأكد من مخرجاتها، وصمم منتجك باش ما يهبطش الشي كامل وقتاها تغلط.
